## Architecture

This project implements a complete monitoring and observability stack on Amazon EKS.

```text
Amazon EKS Cluster
|
+-- monitoring namespace
|   |
|   +-- Prometheus
|   +-- Grafana
|   +-- Alertmanager
|   +-- Prometheus Operator
|   +-- Node Exporter
|   +-- kube-state-metrics
|
+-- apps namespace
    |
    +-- Node.js App
    |   |
    |   +-- /metrics
    |
    +-- Redis
        |
        +-- Redis Exporter

Node.js App -> Prometheus -> Grafana -> Dashboards
Redis -> Redis Exporter -> Prometheus -> Grafana -> Dashboards
Prometheus -> Alertmanager -> Alerts
```

### Monitoring Flow

1. Applications expose metrics through `/metrics`.
2. Prometheus scrapes metrics from configured targets.
3. Metrics are stored as time-series data.
4. Grafana queries Prometheus for visualization.
5. Alertmanager processes alert conditions.
6. Alerts fire when thresholds are exceeded.
7. Dashboards provide real-time visibility into cluster and service health.

### Main Components

| Component | Responsibility |
|---|---|
| Prometheus | Collects and stores Kubernetes, application, and Redis metrics |
| Grafana | Displays dashboards for cluster, app, and Redis metrics |
| Alertmanager | Handles alerts generated by Prometheus rules |
| Node.js App | Example service exposing custom Prometheus metrics |
| Redis | Example backing service monitored through Redis Exporter |
| Redis Exporter | Exposes Redis metrics for Prometheus scraping |
| ServiceMonitor | Tells Prometheus which Kubernetes services to scrape |

### Operational Focus

The project is designed to show the full observability loop: deploy workloads, expose metrics, scrape targets, visualize dashboards, trigger alerts, troubleshoot failures, and clean up AWS resources after testing.
